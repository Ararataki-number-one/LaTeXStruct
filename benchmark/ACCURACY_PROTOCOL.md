# LaTeXStruct 结构分析准确率协议

本协议用于衡量“分析与审阅”是否真的正确，而不是仅统计正则扫描器是否命中一行文字。开发集和冻结外部集必须分别运行；冻结集金标在首次运行前封存。

## 评测单位与合法响应

每个结构单元有唯一、非空且稳定的字符串 `id`，并且只能属于以下一种金标动作：

- `preserve`：已经正确结构化的环境、普通叙述或引用文字，必须保持不动；
- `wrap`：裸写的定理、定义、引理、命题、推论、例、注记、问题或证明，必须使用正确环境包裹；
- `move-boundary`：仅在源文确有可证明的环境边界错误时移动结束边界；
- `manual`：证据不足，必须保留原文并明确交给人工，不能自动猜测。

`none`、缺失动作、缺失自动动作的环境、缺失或倒置的原子块边界均为非法响应，不能等价为 `preserve`。每个送审 `id` 必须恰有一个响应；漏答、重复 `id`、未知 `id`、非法记录都是协议错误，发布门槛要求协议错误为 0。模型无响应时，产品可以生成一个显式的 `manual` 回退记录，但该记录仍按 `manual` 与金标逐字段比较，不能隐藏为“未参与评分”。

一个预测仅在以下四元组完全相等时为正确：

```text
(action, env, start_block, end_block)
```

`env` 在所有动作下都必须是去除首尾空白后的 JSON 字符串；`preserve` 与
`manual` 必须明确写作 `"env": ""`，不得使用 `null`、省略字段或沿用上下文中
其他候选的环境。`start_block`、`end_block` 必须是非负整数，不能用字符串数字。

环境正确但吞入后续段落、漏掉同一证明的段落，均为错误。错误的自动动作、环境或边界同时产生一个 FP（做了错误修改）和一个 FN（应做的正确修改没有完成）。对 `preserve` 或 `manual` 单元执行任何自动修改属于严重错误。

## 指标与公式

令 TP 为四元组完全正确的自动修改数；FP 为错误自动修改数及未知候选输出数；FN 为没有完成四元组金标的应修改单元数。

```text
Precision = TP / (TP + FP)
Recall = TP / (TP + FN)
F1 = 2 * Precision * Recall / (Precision + Recall)
Exact accuracy = 完全正确的全部单元数 / 全部金标单元数
Decision coverage = 合法且唯一的响应数 / 全部金标单元数
Boundary exact match = 四元组完全正确的自动修改数 / 全部金标自动修改数
Preservation accuracy = 正确 preserve 数 / 全部 preserve 金标数
Manual accuracy = 正确 manual 数 / 全部 manual 金标数
```

`manual` 与 `preserve` 分开统计：把需要人工判断的单元无声保留，或把确定安全的负例大量送人工，均不算正确。

除 point estimate 外，发布报告还必须给出上述二项比例的双侧 95% Wilson score interval 下界。成功数为 `x`、样本数为 `n`、`z = 1.959963984540054` 时：

```text
p = x / n
WilsonLower = (p + z^2/(2n) - z*sqrt(p(1-p)/n + z^2/(4n^2)))
              / (1 + z^2/n)
```

F1 下界使用 Precision 下界与 Recall 下界的调和平均。分母为 0 时下界定义为 0，不能用“该类没有样本”得到虚假的 100%。

## 文档级完整性

每份金标文档必须恰有一条独立完整性检查，包含：

- `content_preserved`：正文、公式、引用、标签与宏的语义内容是否完整；
- `resources_complete`：图片等依赖资源是否存在且引用可解析；
- `environments_declared`：结果使用的每个环境是否已有可解析的声明；
- `compile_status`：`passed`、`failed` 或 `not-required`。

只有冻结片段在运行前本来就不能独立编译时，才能使用 `not-required`，并须在抽样清单中说明原因。漏掉、重复、未知或字段非法的文档检查均为协议错误；正文丢失、资源不全或编译失败均为严重错误。

```text
Structural document exact = 所有结构单元均正确的文档数 / 文档总数
Document integrity accuracy = 完整性检查全部通过的文档数 / 文档总数
Document exact rate = 结构与完整性均全部正确的文档数 / 文档总数
```

因此，document exact 不再仅由候选四元组推断，不能在图片丢失或结果不可编译时仍报告 100%。

## 发布门槛

每个开发集或冻结外部集至少包含 600 个单元、6 份文档，并且至少包含 250 个自动修改金标（其中至少 20 个 `move-boundary`）、250 个 `preserve` 金标和 100 个 `manual` 金标。样本规模与类别构成必须在模型运行前冻结，不能通过删掉困难类别提高成绩。金标候选必须先由真实源环境/人工语义独立确定，扫描器输出只能作为被测系统结果；不得要求 `wrap/manual` 先被扫描器命中，或要求 `preserve` 先没有扫描候选，否则会系统性排除端到端漏检与误报。

发布必须同时满足：

- 全部单元的 Exact accuracy 点估计必须严格大于 98%（恰好 98% 不通过）；
- Exact accuracy 的 95% Wilson 下界，以及 Precision、Recall、F1、Decision coverage、Boundary exact match、Preservation accuracy、Manual accuracy 的点估计和 95% Wilson 下界，均不得低于 95%；
- 文档检查覆盖率与文档完整性准确率必须为 100%；Structural document exact 与 Document exact rate 继续逐文档计算、校验并公开报告，但不再要求每份文档的所有普通分类判断达到 100%；
- 协议错误、`preserve`/`manual` 误改、正文/公式/引用丢失、未声明环境、原本可编译而结果不可编译、资源缺失等严重错误均为 0；
- 若模型输出经过确定性安全门，评分器必须校验安全门 manifest，并把门前漏答、重复、未知 ID 与非法记录继续计为协议错误；安全门不得把这些错误“洗成”合法 `preserve/manual`；
- 文档完整性检查必须来自冻结夹具的独立源文件/资源核验，并与安全门实际应用补丁后的内容不变量、资源不变量、括号/环境配平结果合并；评分器不得自行写死为通过；
- 冻结外部集必须覆盖 3 本数学书和 3 篇数学论文；发现错误后可以修复并重跑全套，但报告必须同时保留首次结果和最终结果，且不能把修复所依据的同一冻结集重新称为盲测。

95% 是分类指标及统计置信下限，不等于允许交付已知的破坏性错误。普通且可恢复的 `manual`/`preserve` 分类或安全自动判断错误仍按完整四元组计错，并受“总体 Exact accuracy 严格大于 98%”以及各分类指标下限共同约束；协议违规、内容或资源破坏和不可恢复错误仍然零容忍。逐文档 exact 结果必须公开，不能用总体成绩隐藏错误集中在哪份文档。

## 外部文档抽样

每部作品固定抽取开头、中部、结尾三个区段，并同时包含：

- 已有 theorem/proof/definition 等环境的保持样本；
- 由真实环境生成的 OCR 风格裸标题恢复样本；
- 普通叙述、交叉引用、图表/列表/自定义宏等负例；
- 环境结束后紧邻说明段、多段定理、无 QED 证明等边界压力样本；
- 证据不足、正确动作必须是 `manual` 的对抗样本。

抽样清单、源 URL、版本或 commit、源文件 SHA-256、抽样随机种子、金标、原始模型响应、文档完整性检查和运行结果必须封存，确保结果可重复。
